# Domain docs

GarageOS uses one domain glossary for its backend, dashboard, and customer surfaces.

Before domain design or implementation, read the root `CONTEXT.md` if it exists and the relevant ADRs in `garageos/docs/ADRs/`. Surface any conflict with an existing ADR.

Create `CONTEXT.md` when a domain term is resolved. Keep it a glossary of business concepts and relationships, without implementation details. Record a new ADR in `garageos/docs/ADRs/` only for a hard-to-reverse decision with real alternatives and a reason future contributors would need to know.
